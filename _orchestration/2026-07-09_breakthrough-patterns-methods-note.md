## P9 — Prereg-commit-pushed-first (the freeze is a git fact, not a promise)
A prereg protects nothing if the record cannot establish it was frozen before the numbers were seen; the freeze is claimable ONLY by commit/push ordering. The frozen prereg lands as its OWN commit, PUSHED to origin, before any driver/derivation code exists in the tree — a push timestamp the code cannot predate. **Receipts:** X37 PR #616 — prereg `167f28ce` pushed 26 min before the code, and it survived a gh-api push-timestamp audit (the reviewer pulled the actual push times from the GitHub API and confirmed the ordering); X38 PR #619 — same pattern; **counterexample** X36 PR #613 — prereg and code landed in a single commit, which made the freeze UNCLAIMABLE (review finding MINOR-12): the content may well have been honest, but nothing in git could show it. This is the git-native enforcement of Rule 11 (no post-data bin edits) — it proves none happened — and it pairs with the 2026-07-05 prereg-vs-code diff lens (that lens diffs frozen declarations against shipped code; freeze-by-push makes "frozen" a checkable ordering). **Rule:** freeze the prereg as its own pushed commit before the first line of code; a freeze you cannot point to in the git log is a promise, not a freeze.

## P10 — The entailed-branch check (adjudications must be fireable)
A branch the model class was going to report no matter what is not an adjudication — the honest verb is DEMONSTRATED, not ADJUDICATED. Before freezing a branch set, check each branch against *could the run have come out the other way?* and flag any branch MATHEMATICALLY ENTAILED by the installed structure: a monotone objective (the minimizer is forced), an adjudication rule consuming already-merged inputs (the verdict is a function of frozen data, not the run), or a detector that structurally cannot report one branch (the Step-3.8 degeneracy zeros, generalized). **Receipts — three same-week instances (2026-07):** #613 MAJOR-11 (Branch P entailed by the installed tank), X37 branch-(iii) (entailed by `s=1` fixed pre-driver), X38 branch-(ii) (entailed by the monotone backbone — and the degenerate co-minimum made it worse: the tie means even the "selection" was non-unique). In each, the run *demonstrated* an entailed property; none *adjudicated* an open fork, and the verb was corrected. This is the branch-set sibling of the readout-degeneracy check (P4's refute-structuring, applied to the branch set rather than the observable). **Rule:** before freezing a branch set, state per branch whether it is FIREABLE or ENTAILED; a prereg with no fireable branch has no discriminator and must be reworked.

## P11 — The sabotage test (gates proven fireable by disabling the physics)
A gate that passes with the physics turned off is a self-comparison, not a gate — it would book PASS for any physics including none. Every recovery/consistency/agreement gate must be run once with the parasitics/effect it is supposed to detect DISABLED (zeroed, short-circuited, or dropped to its trivial fallback) and shown to FIRE (report FAIL) before a PASS is trusted. **Receipts — three catches in one week (2026-07):** X36 G2 (bit-level self-comparison) plus G6 (a no-op touching no verdict-bearing quantity); X37 G-B (early-return float-identity, repaired with a loaded-path probe); X38 G-B (the reviewer disabled the parasitics fully and the gate STILL passed at rel 0 — the disabled path fell back to π, the same constant the reference used, so the sabotage test is exactly what fired). This is the gate-side / negative-control member of the liveness triad: P5's readout positive-control proves the meter can see a known-nonzero case, the dead-actuator check (P4/x29) proves the actuator injects one, and the sabotage test proves the gate reports FAIL when the effect is absent. **Rule:** a gate that has never been shown to fail has not been shown to be a gate — disable the physics and confirm it fires before quoting any PASS.

## P12 — Frozen bins enforce, flags don't (a disclosed risk is not a constrained one) [2026-07-10]
A prereg that *names* its own seduction risk in prose has documented the risk, not removed it — the shipped result can still walk straight into it. **Receipt:** X41's prereg flagged its seduction risk explicitly (the #624 rhyme, the 0-for-N ledger, the "no DERIVED-WHY headline" self-instruction), and the shipped result *still* ranked K1 "strongest" over what the frozen adjudication bin recorded as an honest tie (#627 adversarial review finding 10; repair `89f3991b` — "frozen tie restored with per-key cost ledgers, K1 ranking removed"). The disclosure was faithful and the ranking leaked past it anyway, because a paragraph of self-warning has no enforcement — only the frozen bin structure does. This is the P10 sibling at the *verdict* layer: P10 makes each branch fireable-or-entailed before the run; P12 makes the *ranking across surviving branches* a frozen-bin fact rather than a prose judgment the write-up can quietly overrule. **Rule:** bake the constraint into the frozen adjudication bins (a tie is a tie in the bin, with per-branch cost ledgers, and no "strongest" field), not into a prose flag — a risk you only disclosed is a risk you left live.
